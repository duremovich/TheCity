# Architecture

Written 2026-10-18 from the code (the process review, task 5); verified with five lookups (a tip's payment, the hourly LOD assignment, a Statistical agent's meal, a gang's daily economy, `streetwork`'s config section). Two config readers are still marked unverified.

A codemap: where the thing that does X lives. It names only what is unlikely to change: modules, stable function
names, the shape of the tick. The *why* of every mechanism is in its spec under `docs/` (see `docs/README.md`); this
page does not retell them. If a name here stops resolving, fix this page in the same commit. Search tip: most
mechanisms are a `daily(world)` / `hourly(world)` called from a system's `run`; `grep -rn "fn daily" citysim/src`.

## 1. Crates and entry points

**`citysim`** (library, `citysim/src/`): the whole deterministic simulation. No I/O beyond reading `assets/`, no
rendering, no `std::time`, no `HashMap`/`HashSet` iteration (`lib.rs` header). The entry points are `World::new(seed,
Config)` (`world.rs`) and `citysim::tick(&mut World)` (`lib.rs`), which calls `World::tick`. `World::run_ticks(n)` is
the convenience loop tests use.

**`citysim-cli`** (`citysim-cli/src/main.rs`, `shadow.rs`, `import_graphics.rs`): the headless runner. Subcommands
`run`, `calibrate`, `shadow`, `gen-map`, `import-graphics` (section 11). Must run from the repo root so `Config::load`
finds `assets/config.toml` (or set `CITYSIM_ASSETS`).

**`citysim-app`** (`citysim-app/src/`): the macroquad viewer: `render.rs`, `camera.rs`, `input.rs`, the overlays
(`overlay.rs`, `word_overlay.rs`, `contract_overlay.rs`), and the panels in `ui/` (`inspector.rs`, `building.rs`,
`corp.rs`, `district.rs`, `feed.rs`, `log.rs`, …; the inspector's Story tab draws `story::lines`). It reads the world
advances it with `World::run_ticks` and sends `PlayerCommand`s; it never writes components directly.

**`assets/`**: `config.toml` (every number), `stat_table.toml` (generated by `calibrate`), `stat_mlp.toml`, `names.txt`,
the maps (`map.txt`, `map_v1.txt`, `maps/`, `gen_map.py`). **`tools/`**: `test.py` (the tiers, `docs/TESTING.md`),
`analyze_run.py` / `compare_runs.py` (read `run --report --events`), `hooks/` (fmt pre-commit), `train_stat_policy.py`.

## 2. The tick

`World::tick` (`citysim/src/world.rs`) is one in-game minute. It runs a fixed list of systems, in this order, every
tick; each system decides its own cadence inside its `run` by testing `world.tick_of_day()` (0 = midnight) or
`world.tick.is_multiple_of(TICKS_PER_HOUR)`. The doc comment above `World::tick` records why the order is what it is;
read it before moving one.

"<module>::daily\|<module>::hourly"`.

Rule (enforced by `citysim/tests/no_per_tick_scan.rs`): per-tick code never scans every citizen. It reads the tier and
role indices (`World::bodies`, `tier`, `guards`, `workers`). A daily or hourly scan carries a `// scan-ok: <why>`
comment on or above the line.

## 3. Entities, components and the `World`

- `entity.rs`: `EntityId { index, generation }` (generational; `spawn` reuses the lowest freed slot, `despawn` bumps
  the generation). The `Component` trait and the accessors `World::comp`, `comp_mut`, `has`, `insert`, `remove`,
  `with::<T>()` (all ids holding `T`, ascending).
- `components.rs`: plain-data components and shared enums. Every component is a `Vec<Option<T>>` field on `World`,
  indexed by `EntityId.index`.
- `world.rs`: `pub struct World` and the `components!` macro, which is the **registry**: adding a store there wires
  its `Component` impl and the spawn/despawn grow/clear. A new store also needs a line in `World::resize_stores` if it
  may be omitted from a save.
- Derived indices are not saved and are rebuilt by `World::rebuild_indices` after a load (neighbours, spouses,
  enemies, tiers, asset indices, Virt indices, hunts, hangouts, contracts).
- The social graph: `World.edges` (`edge_map.rs`, keyed `(min, max)`, iterates in key order), with `World::edge`,
  `edge_entry`, `remove_edge`, `neighbours`.
- `spatial.rs`: `TileGrid`, a bucket grid for radius queries; returns a superset the caller filters.
- `map.rs` (tile map from `assets/map.txt`), `mapgen.rs` (generated maps, `--map gen:<N>`), `time.rs` (ticks, days,
  `DayPhase`, `Season`; `TICKS_PER_DAY`, `TICKS_PER_HOUR`).

The tier lists: `World.by_tier: [Vec<EntityId>; 3]` (indexed `Lod as usize`, ascending) and `World.stat_slots` (the
Statistical tier bucketed by `id.index % 60`). Kept by `World::index_brain` / `unindex_brain`; read through
`World::tier(lod)` and `World::bodies()` (Full + Coarse merged).

What each thing is:

- **Agent**: an entity with `Identity`, `Position`, `Needs`, `Personality`, `Mood`, `Wallet`, `Inventory`, `Brain`,
  `Memory`, `Skills`, `Body`, … plus optional `Job`, `Household`, `GangMember`, `Sentence`, `Child`, `Squatter`.
  Living adults: `World::citizens()`; with a Brain: `World::brained()`. Death (`World::kill` / `kill_by`) strips all
  but `Position` and `Identity` and adds `Corpse`; `Trace` and `Life` are kept after death. `World::remove_agent`
  frees an emigrant.
- **Building**: an entity with `Building` (`kind: BuildingKind`, `rect`, `door`, `owner`, `occupants`, `tier`,
  `rent_per_day`, stock, …); a Market also carries `Market`, the Jail `Law`; the city's `Treasury` is a component on the Hall building (`World::treasury()` reads `building_of_kind(BuildingKind::Hall)`). Per-kind numbers: `Config::buildings.for_kind(kind)`
  (`[buildings.*]`).
- **Corp**: its own entity carrying `Corp` (treasury, orders, niches). `World::corps()`.
- **Gang**: its own entity carrying `Gang`. `World::gangs()`.
- **Asset**: its own entity carrying only `Asset`; indexed in `assets_at` / `assets_by_owner`. `Kit` is derived per
  agent from its assets, never saved.
- **District**: not an entity: `World.districts: Vec<District>`, indexed by `DistrictId(u8)`; the tile grid is rebuilt
  by `districts::rebuild` on load.
- **Outside parties** (the World account, parents): not entities; accounts on `World.outside` (`outside.rs`), numbered
  from `OUTSIDE_PARENT_BASE`.

## 4. LOD tiers

`components::Lod` has three values: `Full`, `Coarse`, `Statistical`. Ambient is not a `Lod`; it is households that are
not agents at all.

- **Assignment**: hourly in `systems::lod::run` → `assign_hour` → `assign`, ranking agents by `rank_class` /
  `class_with` (pinned, on screen, story-relevant plan steps via `story_relevant`, the forced quotas from
  `budget_sets`: gang, private guards, raids, prisoners) into `[lod] max_full` and `max_coarse`, with hysteresis.
  `[lod] force` overrides all of it (`--force-lod`). Every tier change goes through `lod::set_lod`, which converts the
  exec state and, on promotion, queues the agent's open holes for the binder. `Brain.pinned` keeps an agent Full (the
  shadow tool uses it).
- **Full**: everything: needs per tick, think, plan, exec with tile-by-tile walking (`exec::walking_goto`, flow fields
  in `exec/flowfield.rs`, paths in `exec/pathfind.rs`, `exec/bigpath.rs`).
- **Coarse**: the same brain and plans, but a `GoTo` is a timed jump (`exec::timed_goto`), no per-tile walk. Agents
  promoted by a story (a bind, a hunt, a captive) usually enter here. Sentenced prisoners are held Statistical (`[lod]
  held_prisoners`, `lod::is_held`).
- **Statistical**: no think, plan or exec. `lod::run_statistical` runs each agent once an hour on its slot tick and
  replaces the brain with rolls from a `StatRow`: `stat_eat`, `stat_work`, `stat_earn`, `stat_theft`, `stat_flirt`,
  `stat_social`, `stat_rolls` (robbed, beaten, killed: each opens a `Hole`, section 10), etc. All draws from the
  agent's own stream (`SimRng::agent`).
- **The policy** (`systems/stat_policy.rs`): `[lod] policy = "table"` (default; `assets/stat_table.toml`, 24 rows by
  phase x lawfulness bucket x hunger bucket, loaded by `world::load_stat_table`) or `"mlp"` (experiment). The policy
  changes only the probabilities, never the order of the rolls.
- **Calibration**: `citysim-cli calibrate` runs Full cities and writes `stat_table.toml`. A regen redraws rare rates;
  check the run report against main before shipping one.
- **The parity rule**: Full-tier and Statistical-tier rates must agree within 15 %
  (`citysim/tests/lod.rs::test_full_vs_statistical_within_15pct`, milestone tier). Every Full-tier mechanism states
  its Statistical mirror or why it has none. Violence rates by order and district reach the Statistical tier through
  the order-rates ledger (`ledger.rs`, `systems/fviolence.rs`).
- **Ambient** (`ambient.rs` types, `systems/ambient.rs` logic; `[ambient]`): a Home's flats beyond its household slots
  hold households that are a pure function of `(world seed, building, flat index)` and store nothing. They become
  Statistical agents by materialisation (the labour pool, immigration, `ambient::touch`). `ambient::daily` writes
  district aggregates. No world-stream draw.

## 5. The brain: utility → GOAP → exec

1. **Goal selection** (`utility/`). `systems::think::run` schedules: each body thinks every `[brain]
   think_interval_ticks`, staggered by `id.index`, plus one urgent think when its plan ends. `think_once` calls
   `utility::think` / `think_with_offer` (`utility/mod.rs`), which scores every goal in `utility::goals::GOAL_ORDER`.
   A goal's inputs are `utility::goals::considerations(world, id, goal, has_spouse)` (one big `match` on `GoalKind`);
   `utility::score_goal` multiplies them (any zero = unavailable), applies `compensate` (Dave Mark), hysteresis and a
   flat bonus. Curves are in `utility/curves.rs`. `already_satisfied` drops goals with nothing to do. Some goal blocks
   delegate to their system (e.g. `leisure::considerations` for Unwind). On a change of goal the plan is aborted
   (unless uninterruptible) and the agent queued.
2. **Planning** (`systems/plan.rs`, `goap/`). `plan::run` pops `(urgency, agent)` from `World.plan_queue` within
   `[brain] plan_budget_per_tick` and `plan_expansion_budget_per_tick`. Some goals bypass the planner with scripted
   plans in `exec/routine.rs` (`idle_plan`, `commute_plan`, `raid_plan`, `grocery_plan`). The rest: build a `PlanCtx`
   (`goap::actions::PlanCtx::build_for`), observe a `WorldState` (`goap/world_state.rs`), take the goal's target state
   from `goap::goal_state(goal)`, and run `goap::planner::plan` (forward A* over `WorldState`, heuristic `H_PER_KEY`
   per unsatisfied key). The plan is installed on `Brain.plan` with its reservations (`exec/reservations.rs`).
3. **Execution** (`exec/`). `exec::run` → `step_agent` → `start_step` / `advance_goto` / `arrive`. Three executor
   states (`ExecState`: Goto, Use, Wait, after F.E.A.R.). The per-action rules are in `exec/actions.rs`: `duration`,
   `can_start`, `on_start` (money moves at start), `on_complete` (every other effect), `on_abort`, `finishes_early`,
   `on_arrive`.

**The planner key**: `WorldState::pack` packs the state into a `u64` (`at` in bits 0-7, two 2-bit counters, then one
bit per flag from `FLAG_BASE`; at most `MAX_FLAGS` flags). The destructuring is exhaustive, so a new `WorldState`
field fails to compile until it is packed. `citysim/tests/planner_key.rs` proves the packing injective and the plans
identical to an unpacked reference search.

**Registering a new goal**: a `GoalKind` variant (`components.rs`) → its slot in `GOAL_ORDER` (and the matching
`GOAL_PROF_NAMES` entry in `utility/mod.rs`) → its arm in `utility::goals::considerations` (and `already_satisfied` if
needed) → its target in `goap::goal_state` (or a scripted plan in `plan.rs` / `exec/routine.rs`). A scripted goal is
listed in three places: `goap::goal_state` (`return None`), `plan::plan_for`'s bypass (its `plan` fn) and
`exec::start_step`'s `scripted` match (its own `can_start`); `GoalKind::Visit` (`systems/household.rs`) is the smallest
example: `GoTo(Victim) → Rest`, with the completion read in `actions::on_complete`'s `Rest` arm by the plan's goal.

**Registering a new action**: an `ActionKind` variant (`goap/actions.rs`; enum order is the tie-break) → `PLANNABLE`
if the planner may pick it → its arms in `allowed`, `preconditions`, `feasible`, `apply`, `cost`, `instance` (`impl
ActionKind` in `goap/actions.rs`) and `implemented` → its arms in `exec/actions.rs` (`duration`, `can_start`,
`on_start`, `on_complete`). New planner facts are `Key` variants and `WorldState` fields (then `pack`).

## 8. Money

- **Purses**: an owner is `Option<EntityId>`; `None` is the city Treasury. `World::purse(owner)` and `purse_add`
  (`systems/ownership.rs`) dispatch on the owner's kind: an agent's `Wallet.coins`, a gang's `Gang.treasury`, a corp's
  `Corp.treasury`, the city's `Treasury.coins`. Charities hold a purse on their `Building` (`charity::purses`).
- **The one transfer path**: `ownership::pay(world, from, to, amount, flow)` (capped at the payer's purse, never below
  0) and `ownership::charge` (a corp or the city pays in full and may go negative). Both go through the private
  `transfer`, which books the `Flow` ledger column and withholds tax where the flow is taxed. `Flow` (in
  `ownership.rs`) names what a payment is for. Never write to a purse directly.
- **Crossings** (coins entering or leaving the city): `ownership::cross_in(world, from_outside, to, amount, flow)` and
  `cross_out(…)`. The outside accounts live on `World.outside` (`outside.rs`): the World account
  (`outside::WORLD_ACCOUNT`, booked by `systems/world_market.rs`) and the parents (`systems/parents.rs`).
- **Escrow**: `ownership::escrow_in` / `escrow_out` move coins onto and off a contract record (`World.contracts`,
  `contract.rs`); `World.escrow_held` tracks the total.
- **The identity**: `econ::identity(world) = ownership::total_coins + Σ outside treasuries − outside.minted` is
  constant to the coin (`systems/econ.rs`). `total_coins` counts wallets, gang, corp and city treasuries, unsettled
  corpse loot, escrow and loot in flight on open holes. A coin made or lost is a gate failure; tests assert
  `econ::identity` before and after.
- `ledger.rs` is **not** money: it is the order-rates ledger of violence (section 4).

## 9. Determinism, RNG, saves

- `rng.rs`, `SimRng` on `World.rng`: the **world stream** (`rng.world()`: spawning and older systems), one **agent
  stream** per entity (`rng.agent(id)`, the Statistical tick), and fresh, never-stored, keyed streams: `hole(id)`,
  `keyed(key)`, `run(run, contest)`, `word(ns, a, b)`, `contract(ns, a, b)`. Each kind owns its bits of the stream id
  (`stream_id_*`), so they never collide; `rng.rs`'s own tests check that.
- **Pure hashes**: `rng::splitmix64` and `systems::econ::{hash_unit, hash_normal}(seed, purpose, a, b)` with a purpose
  constant unique to the call site (e.g. `econ::PURPOSE_*`).
- **The rule**: a new mechanism never draws from the world stream. It uses a keyed stream or a hashed purpose unique
  to its site, so an off switch leaves every other draw where it was and the switched-off city is byte-identical to
  main.
- No `HashMap`/`HashSet` iteration and no wall clock in sim code. Ordered maps are `BTreeMap` / `BTreeSet`; `EdgeMap`
  sorts when iterated.
- **Saves** (`save.rs`): the whole `World` as compact RON (`to_ron`, `from_ron`, `save_to_file`, `load_from_file`,
  `newest_save`; files `saves/<seed>-<tick>.ron`). Same world ⇒ same bytes. `from_ron` resizes the stores, rebuilds
  indices, districts and the transit network, and runs version migrations gated on `world.save_version`.
  `SAVE_VERSION` (top of `save.rs`, with a changelog comment) is bumped on every change to the saved shape; new fields
  use serde defaults.
- **What the tests check**: `tests/determinism.rs` (same seed ⇒ same blake3 hash of the save, a different seed ⇒ a
  different one); `tests/save.rs` (save mid-day, mid-hunt, mid-contract, load, run both on, the hashes agree with each
  other and with an uninterrupted run).
- `levers.rs`: every `PlayerCommand` is applied at the next tick start and logged with its tick, so a save plus its
  command log replays exactly (`tests/lod.rs::test_command_log_replay_matches`).

## 10. Events, memory, story, the binder

- **Events** (`events.rs`): `World.events`, a ring of `EVENT_RING_CAP` `Event { id, tick, kind, actors, text }`, never
  drained; ids are contiguous over the run (`World.next_event_id`), so the binder can rewrite an entry by id
  (`World::event_mut`). Append with `World::push_event(kind, actors, text)`. A reader keeps a cursor on
  `next_event_id` (the CLI's `--events`, the app's log). `PlanAborted` goes to the unsaved `debug_events` ring
  instead.
- **Memory** (`Memory` in `components.rs`, logic in `systems/memory.rs`): `entries` are first-hand (`World::remember`,
  `remember_crime`; capped by `[brain] memory_cap`, smaller for Statistical agents, which keep only a whitelist of
  kinds), evicted by lowest `salience × recency`, decayed daily. `heard` holds rumours and sightings from talk
  (`systems/gossip.rs`), capped separately; no talk evicts a first-hand entry.
- **The word** (`word.rs` types; `systems/word.rs` daily chain): deeds, district rumour pools, reputation
  (`systems/reputation.rs`), grudges, hunts, Feeds (`systems/news.rs`).
- **Holes and the binder** (`systems/bind.rs`): a Statistical roll that something was done *to* an agent opens a
  `Hole` (`World.holes`) without naming who. The binder names it from the candidates' `Trace`s, on the hole's own
  stream (`SimRng::hole`): daily for consequential or expired holes, at once for a promoted victim
  (`bind::drain_queue`), and on demand from the inspector.
- **Biography** (`story.rs`): `lines` merges an agent's `Life` events with runs of `Trace` days into `StoryLine`s for
  the app's Story tab. `Trace` is written at day end by `systems/stats.rs`.

## 12. How to add a mechanism

Checklist (the doctrine is in `CLAUDE.md`; test rules in `docs/TESTING.md` and `.claude/rules/tests.md`):

1. **Config key** in its section of `assets/config.toml`, with a comment like its neighbours (what, why, the spec
   item), and the matching field + `Default` value in the section's `Cfg` struct in `config.rs`. No literals in
   systems.
2. **State**: a field on an existing component, a new component (register it in `components!` and `resize_stores`), or
   a `World` field. Derived indices are rebuilt in `rebuild_indices`, not saved.
3. **The system fn**, placed in the tick: a `daily`/`hourly` in the owning `systems/` file, called from the `run`
   whose position in `World::tick` gives it the state it reads. Per-tick code reads tier/role indices only (`scan-ok:`
   otherwise). Brain changes: section 5's registration lists.
4. **Randomness**: a keyed stream or a hashed purpose unique to the site; never the world stream.
5. **Money** moves only through `ownership::pay` / `charge` / `cross_*` / `escrow_*` with a `Flow`.
6. **The Statistical mirror** in `systems/lod.rs` (a `stat_*` roll, a stat-table row, or a ledger rate), or a written
   reason why none is needed; check the parity test still holds.
7. **Visibility**: `World::push_event` for story events; `DailyStats` counters for the run report; gate numbers print
   as `FINDING` lines (`eprintln!("FINDING …")`), never asserts.
8. **`SAVE_VERSION`** bumped in `save.rs`, with a line in its changelog comment, if the saved shape changed; new
   fields take serde defaults.
9. **A unit test in a seeded world** that fails on the base: build the world, set the preconditions by hand, call the
   system, assert the effect, ideally against a control. Helpers live in `citysim/tests/common/mod.rs` (`mod common;` at the top of the test file): `world`, `dole_world`, `world_with`, `run_days`, `adults`, `coins`, `set_coins`, `corp_named`.
10. **The off switch** while the phase is in flight (a config `enabled` flag and/or a `CITYSIM_<NAME>_OFF=1` env var
    read in `Config::load_from`); off must be byte-identical to main on seeds 42-44 x 30 days. Retire it when the
    phase lands.
11. **The spec**: write any deviation into the milestone spec (with an `OPEN-nnn` tag if it leaves work open), and
    state the Statistical mirror in the commit.

### Worked example: Shadow V4 bug 21, one deed in at most N Feeds (`79af4bc`)

A 20k shadow saw one assault run in 11 corp Feeds. The fix is item 21 of commit `79af4bc` (a commit that batches six
fixes; `git show 79af4bc -- assets/config.toml citysim/src/config.rs citysim/src/systems/news.rs
citysim/tests/news.rs` isolates it).

| step | what the commit did |
|---|---|
| 1 config | `[news] outlets_per_deed = 2` in `assets/config.toml`, commented with the bug and the 20k observation; `NewsCfg.outlets_per_deed: u8` with a doc comment ("0 = any number") and `2` in `impl Default for NewsCfg` |
| 2 state | none: it reads the existing `World.stories` |
| 3 system | a helper `outlets_running(world, deed, actor, object)` in `systems/news.rs`, and one guard in `run_stories` (reached from `news::daily`, inside `word::run`'s midnight chain) that skips a deed already run by `outlets_per_deed` Feeds within `RECENT_DAYS` |
| 4-5 RNG, money | none drawn, none moved |
| 6 mirror | none needed: Feeds read the district pools, not the tier |
| 7 visibility | the story records themselves |
| 8 save | no bump: no saved shape changed besides the saved config, whose `NewsCfg` is `#[serde(default)]` (the changelog bumps when a new *section* joins the saved config; a single key with a serde default loads either way) |
| 9 test | `tests/news.rs::test_one_deed_in_at_most_outlets_per_deed_feeds`: a seeded city, the pools cleared, one killing posted to every district, `news::daily` called; the control (cap 0) runs it in both Feeds, cap 1 in exactly one. It failed on the base `ce5afe6` |

| 11 spec | the commit message names the bug number; the bug is item 21 in `docs/SHADOW_V4.md` › Bugs |
